双流目标检测实验命名规则
========================

一、总体原则
------------

Ultralytics 训练目录使用 project 和 name 两级管理：

project：表示长期稳定的“数据集 + 任务 + 研究方向”，不要随单次架构变化而改变。
name：表示本次实验的论文来源、迁移模块、融合尺度、关键架构参数和版本。

固定格式：

project = {Dataset}_{Task}_FusionTransfer
name    = {Paper}_{Module}_{Stages}_{Heads}_{Structure}_{Version}[_{Seed}]

当前工程统一使用：

project = DroneVehicle_OBB_FusionTransfer


二、name 各字段含义
------------------

1. Paper：思想或模块的论文来源

   示例：ASSANet、MBNet、Restormer、SwinTransformer。

2. Module：迁移到双流检测后的模块名称

   示例：ASSAFusion、DMAF、MDTAFusion、WindowFusion。

3. Stages：模块实际使用的特征尺度

   P345：P3、P4、P5 均使用。
   P45：只在 P4、P5 使用。
   P4：只在 P4 使用。
   P35：只在 P3、P5 使用。

   尺度必须按 P3、P4、P5 的顺序书写。

4. Heads：各融合尺度对应的注意力头数

   H2-4-8：P3=2 heads、P4=4 heads、P5=8 heads。
   H4-8：当 Stages=P45 时，表示 P4=4 heads、P5=8 heads。
   H4：当 Stages=P4 时，表示 P4=4 heads。
   HNA：模块不使用多头注意力，heads 不适用。

   Heads 中的数字必须与 Stages 一一对应，不能省略中间尺度后仍写成三组数字。

5. Structure：只记录能够区分模型架构的关键设置

   多个设置使用短横线连接，例如：

   DynK3-FFN2       动态 3×3 局部卷积，FFN expansion=2。
   DynK3-NoFFN      动态 3×3 局部卷积，不使用 FFN。
   StaticDW-FFN2    静态深度卷积，FFN expansion=2。
   W7               Window size=7。
   Base             没有需要额外说明的结构变体。

   batch、epochs、workers、device、imgsz 等普通训练参数不要写进名称，
   这些参数由训练目录中的 args.yaml 保存。

6. Version：同一套架构定义的实现版本

   使用 v1、v2、v3……递增。
   只有代码实现或结构定义发生变化时才提升 Version。
   单纯修改学习率、batch、epochs 不提升 Version。

7. Seed：可选的重复实验随机种子

   使用 S0、S1、S2……表示。
   只有同一架构需要多次重复训练、统计均值和方差时才添加。


三、当前 ASSAFusion 实验名称
--------------------------

当前 P3、P4、P5 均使用 ASSAFusion，heads 分别为 2、4、8，
动态卷积核为 3×3，FFN expansion=2，因此命名为：

project = DroneVehicle_OBB_FusionTransfer
name    = ASSANet_ASSAFusion_P345_H2-4-8_DynK3-FFN2_v1

训练代码示例：

results = model.train(
    ...,
    project="DroneVehicle_OBB_FusionTransfer",
    name="ASSANet_ASSAFusion_P345_H2-4-8_DynK3-FFN2_v1",
)


四、ASSAFusion 后续消融实验示例
-----------------------------

1. 只在 P4、P5 使用，heads 分别为 4、8：

   ASSANet_ASSAFusion_P45_H4-8_DynK3-FFN2_v1

2. 只在 P4 使用，heads=4：

   ASSANet_ASSAFusion_P4_H4_DynK3-FFN2_v1

3. P3、P4、P5 均使用 4 heads：

   ASSANet_ASSAFusion_P345_H4-4-4_DynK3-FFN2_v1

4. 去掉 FFN：

   ASSANet_ASSAFusion_P345_H2-4-8_DynK3-NoFFN_v1

5. 将动态卷积改为静态深度卷积：

   ASSANet_ASSAFusion_P345_H2-4-8_StaticDW-FFN2_v1

6. 同一架构使用三个随机种子重复训练：

   ASSANet_ASSAFusion_P345_H2-4-8_DynK3-FFN2_v1_S0
   ASSANet_ASSAFusion_P345_H2-4-8_DynK3-FFN2_v1_S1
   ASSANet_ASSAFusion_P345_H2-4-8_DynK3-FFN2_v1_S2


五、迁移其他论文架构的示例
------------------------

MBNet 模态融合思想：

MBNet_DMAF_P345_HNA_Base_v1

Restormer 的 MDTA 改造成跨模态融合：

Restormer_MDTAFusion_P45_H4-8_FFN2_v1

Swin Transformer 窗口注意力改造成跨模态融合：

SwinTransformer_WindowFusion_P345_H4-8-16_W7_v1


六、命名检查清单
----------------

开始训练前依次确认：

1. Paper 是否准确表示论文来源。
2. Module 是否与 YAML 和代码中的模块名称一致。
3. Stages 是否与真实插入的 P3/P4/P5 位置一致。
4. Heads 数量是否与 Stages 按顺序一一对应。
5. Structure 是否只包含关键架构差异。
6. Version 是否与当前实现版本一致。
7. 重复实验是否正确添加 Seed。
8. 不要使用含义不清的名称，例如 test、new、final、final2、best_model。


七、永久实验 ID 与 Manifest
---------------------------

长名称继续负责描述架构，但不再单独承担实验身份和文件关联。每个实验还必须分配一个
永久 ID，例如 DarkAct 系列使用 DA-001、DA-002……。ID 一经分配不得因文件改名、
训练重跑或结果目录变化而复用给其他架构。

二者职责如下：

1. ID：稳定身份和父子谱系，例如 DA-005。
2. name：继续遵循本文前述格式，完整描述论文、模块、尺度、heads、结构和版本。
3. Manifest：记录 ID、父实验、唯一改动、YAML、模块源码、初始化权重、迁移脚本、
   Trainer、历史运行目录和报告路径。
4. Seed/重复训练：仍在 name 中按 S0、S1……区分，同时归属于同一个架构 ID。

实验索引与使用命令：

   experiments/INDEX.md
   experiments/<family>/README.md

   python tools/experiment_registry.py validate
   python tools/experiment_registry.py render
   python tools/experiment_registry.py list --family DarkAct
   python tools/experiment_registry.py show DA-005

新增实验时的顺序固定为：

1. 先分配永久 ID，并选择 parent_id。
2. 新增模型 YAML 和迁移权重。
3. 写 Manifest，明确相对父实验的唯一结构变化。
4. 运行 validate 和 render。
5. 使用 tools/train_experiment.py 按 ID 启动训练。

已有 YAML、历史训练目录和旧训练脚本不因登记 ID 而移动或改名；Manifest 只建立
稳定映射，避免破坏续训、评测和既有分析报告。


八、预训练权重迁移公平性约定
--------------------------------

所有新架构和消融实验的迁移源必须直接为：

   /media/biiteam/新加卷/biiteam/MCONG/Yolov8_TwoStream/pre-pth/yolov8s-obb.pt

不得从任何已迁移的双流 checkpoint、中间实验 best.pt/last.pt 或其他实验权重
二次迁移。新模块的随机初始化必须使用明确且相同的迁移随机种子，checkpoint
的 migration 元数据必须记录源绝对路径、SHA256、迁移随机种子和实际复制张量数。
